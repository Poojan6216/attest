# Attacks that work

What Attest knowingly does not catch, with the rate we measured. Sprint 6 adds the red-team results; until then this page holds the limits accepted when Sprint 1 closed. Each one is also an entry in [`Decisions.md`](../Decisions.md) and a rule in [`docs/grading.md`](grading.md).

| Limit | What happens | Measured rate | Where it is written down |
|---|---|---|---|
| Two tabs sight one calendar event, the later sighting is stored first | The earlier sighting is refused (`late_sighting`) and the pass is DEGRADED, but the stored row keeps the later first sighting, so a calendar event that already existed can still verify a "created" claim. The stored row cannot move, because a batch may already have graded with it (Hard Rule 4). | 25 of 513 minute-precision `calendar.created` receipts (4.9%) in the differential simulator, with 25% of rows re-sighted by a second tab within ±30 minutes | [§4.1](grading.md#41-window), Decisions `[1.close-r4]` |
| A FINAL-to-NOT_FOUND override is reverted while another claim holds that evidence | The reverted receipt shows its computed VERIFIED or PARTIAL again, while the evidence stays with the other claim; one observation is never fixed to two claims (Hard Rule 4). The Sprint 4.3 revert control must say so. | 15 of 7,277 receipts with a reverted override of that kind (0.21%), 5,000-seed simulator | [§8](grading.md#8-state-machine-conditionsts-decides-finality-statets-applies-events), Decisions `[1.close-r3]` |
| A PENDING UNASKED row holding a reverted override is no longer produced by later batches | The row is kept, PENDING, so replay still sees the orphan that batches took while the override was in force, until a batch produces it again or a FINAL claim supersedes it. | 71 of 7,753 claim-less receipts with reverted overrides (0.92%), same simulator | [§8](grading.md#8-state-machine-conditionsts-decides-finality-statets-applies-events), Decisions `[1.close-r3]` |
| Deliberately evasive code inside `src/core` | The purity and Unicode fences (lint, the grep gate, the syntax-tree Unicode fence, the runtime guard under `pnpm test:poison`) catch impurity written by accident or through ordinary idioms. Code written to dodge them (names built from fragments, reflection chains built to reach a built-in, code that blinds the guard) is a code-review matter for the sprint-end security and tech reviews. | Today's `src/core`: 0 findings in every layer. 49 ordinary-idiom probes (stray browser globals, beacons, locale and time-zone reads, type-check switches, Unicode idioms) each fail at least two layers. | [§14 item 9](grading.md#14-deviations-from-build_spec-7-all-in-decisionsmd-sprint-1), Decisions `[1.close-r3]`, `[1.close-r4]`, `[1.close-r5]` |
