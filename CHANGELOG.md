# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). `0.1.0` is the first store release.

## [Unreleased]

### Added

- WXT + Manifest V3 + Preact + Tailwind scaffold with TypeScript strict, `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`, and a strict extension CSP.
- Workspace commands, run from the repository root: `pnpm dev`, `pnpm build`, `pnpm build:release`, `pnpm lint`, `pnpm format`, `pnpm typecheck`, `pnpm test` and `pnpm e2e`.
- Lint fences: `attest/no-act` (no clicks, events, DOM writes, navigation or network in anything that reads a vendor page), `src/core` purity (no impure imports, globals, clock or randomness), `attest/top-level-listeners` (MV3), and `console` only in `src/log.ts`. Inline disables have no effect in fenced scopes.
- `src/log.ts`, the only logger: prints identifiers and shapes, never free-form strings.
- Test rails: Vitest + fast-check, Playwright loading the real build in Chromium, a localhost fixture server, and `pnpm bench` generating `RESULTS.md`.
- Two `@mandatory` E2E tests: nothing leaves the browser (5-minute session, NetLog attribution, negative controls) and no seeded secret leaks into export, IndexedDB, storage, console or network.
- Ledger: Dexie schema v10 (sixteen tables: the Calendar snapshots, the coverage intervals, the activity, the alerts, the weekly digests and the three replay stores among them), typed repositories, idempotent upserts, migrations and a deterministic export.
- Typed message bus with Zod validation on both ends.
- `policy/default.json` and a pure, frozen policy loader.
- `pnpm capture`: a read-only fixture capture tool with a PII sanitiser.
- Options page shell with a resettable install id; `PRIVACY.md` v0.
- Service worker wiring: bus, install handler, and a daily purge of facts older than the history you choose to keep (90 days until you change it).
- Readers for your own Gmail and Google Calendar tabs (`src/observers`): the Gmail Sent folder, receipt emails you open (seven platform parsers and a generic one), and the Calendar views you open. Attest asks Chrome to read `mail.google.com` and `calendar.google.com`, and reads them only in tabs you open; it does not run in incognito windows.
- The options page exports the whole ledger as one JSON file, in the ledger's export format, with each receipt's inputs and policy, so `pnpm attest replay` can prove every receipt from it.
- CI on GitHub Actions.
- The grading core (`src/core`): pure functions that compare an agent's claims with what your Gmail and Calendar tabs showed and issue one receipt per claim: VERIFIED, PARTIAL, NOT FOUND, UNASKED, OVER SCOPE or UNVERIFIABLE. Scores are exact fractions, so no rounding ever decides a grade, and every number comes from `policy/default.json`. Attest says NOT FOUND only after every relevant tab was seen over the whole claim window and the grace period passed; with less to go on, the receipt says UNVERIFIABLE.
- Normalisation of addresses, names, subjects, amounts and vendor-relative times ("2:03 PM", "Yesterday"). A look-alike address (a dotless `ı`, a `xn--` domain) is flagged, never treated as the real one.
- Redaction: an observation keeps only the fields the policy allows for its source, and is named by a hash of that content.
- One-to-one matching: one sent email or calendar event verifies at most one claim.
- Receipt states: PENDING (shown as "checking"), FINAL and USER_OVERRIDDEN. An override to VERIFIED or NOT FOUND sits beside the computed grade, never replaces it, and can be undone; the side panel's receipt detail sets one.
- UNASKED receipts for actions no claim explains, when attribution signals (an agent session, you being idle, an agent's signature, its activity log) point to an agent. They always say "likely".
- Scope checks: an action type outside the grant, a counterparty outside the allowlist, one purchase or the rolling total over the spend ceiling, and permissions an agent holds beyond the ones you declared.
- Replay: `pnpm attest replay <export.json>` re-derives every stored receipt from its stored inputs and lists each mismatch ([docs/grading.md §9](docs/grading.md#replay-procedure)). The extension's own export carries those inputs.
- [docs/grading.md](docs/grading.md): the grading contract, with every grade, rule, feature and window, the receipt state diagram, the replay procedure and worked examples.
- 115 golden scenarios ([extension/tests/golden/](extension/tests/golden/)) with hand-computed expectations, property tests for determinism, redaction and replay, a test that runs `src/core` with every clock, randomness, time-zone, locale, timer and network global poisoned, and perf gates for candidate lookup and batch grading (5,000 claims against 50,000 observations; measured numbers in [RESULTS.md](RESULTS.md)).
- `pnpm check-docs`, run by `pnpm lint`: every relative link, anchor, quoted `pnpm` script and policy rule id in the docs must exist (a `cd` inside a subshell `( … )` ends with it); docs/grading.md §15 must document every key of the golden file format; no Markdown file may hold an absolute path from one machine; and Decisions.md entries from the Sprint 1 close on say what was decided, not how the work was organised.
- `pnpm test:coverage`: `src/core` coverage, failing below 95% of lines. CI runs it.
- `pnpm test:coverage:observers`: `src/observers` coverage over the suites that run the observers, failing below 85% of lines. CI runs it.
- `pnpm test:coverage:ui`: coverage of `src/ui` and the four pages (popup, side panel, options, digest) over the suites that render them, failing below 70% of lines. CI runs it.
- `pnpm test:poison`: every core, golden and property test runs with every clock, randomness, time-zone, locale, timer and network global poisoned before `src/core` loads, and fails on any impure call, any changed built-in, or less than 95% of `src/core`'s lines run. CI runs it. What the purity checks cannot catch is listed in [docs/grading.md §14](docs/grading.md#14-deviations-from-build_spec-7-all-in-decisionsmd-sprint-1).

- The founder's first real captures, labelled, beside the synthetic pages: 8 Gmail pages (three Sent pages, a second account's Sent, Drafts, Inbox, two opened Sent threads) and 9 Google Calendar pages (a week before and after creating, moving and deleting a test event, a month, calendars ticked and unticked). The receipt captures are held out until re-captured with the stricter sanitiser. The benches say how many of the pages they score are real, and a test decodes every link and token of every capture (compressed and encoded forms included) and fails on any address that is not a fake.

- `docs/claims-import.md` v1: the design for taking an agent's claims from a log the person pastes into the side panel, since Attest reads no agent's site (tasks 3.11 to 3.14).
- `docs/privacy-architecture.md` v1: every ledger table and field, the allowlist of each observation source, what is hashed and what that does not hide, retention and purge, and the export.
- `pnpm check-docs` also fails when `docs/privacy-architecture.md` does not describe a field `policy/default.json` allowlists, or describes one it does not (`scripts/check-docs-allowlist.ts`).

- Claim pattern tables for the agent adapters (`src/adapters/patterns.ts`): a sentence an agent writes is read as one of the eight action types only when it reports the action done. A question, an offer, a draft or an approval prompt is recorded as `other` at low confidence, and a refusal or a step still under way is no claim, so a misread sentence loses a claim rather than inventing one. Each vendor's table is tested on 47 or 48 invented sentences plus 20 shared ones.
- The agent adapter skeleton (`src/adapters/base.ts`): each pass on a Muse, ChatGPT or Claude page reports its health, the requests the user made, the claims the agent's sentences make, and on a settings page the apps the agent can reach (a new bus message, `adapter.scope`). A claim whose time the page does not show is left out and the adapter shows as degraded, rather than placed at a guessed time. No vendor adapter uses it yet; each waits on captured pages.
- The Muse adapter (`src/adapters/muse/`), written against five hand-made Muse pages until real ones are captured: the requests in a conversation, the actions the replies claim, the activity view, and the apps switched on in the connected-apps settings. An approval prompt is recorded as a proposal, never as the purchase it asks about, and a text Muse quotes or an approval card beside a message is never read. It runs nowhere until Muse's web address is confirmed.
- A reader for an agent's activity log that you paste (`src/adapters/paste.ts`): each entry becomes a claim through the same pattern tables and ids as the page readers, at the time the log shows, on the day of the heading above it. An entry whose day or time the paste does not show is listed as "no day" or "no time" and not imported, never placed at a guessed time, and pasting the same log twice adds nothing. Nothing calls it yet; the side panel's paste box comes next.
- The side panel's **Add agent activity**: choose the agent, paste its activity log, and preview each claim Attest found (what, who or what, when) and each entry it will not import, with why. Import sends only the claims; the text is dropped once the preview closes and is never stored. The paste box has spell check off, since Chrome's enhanced spell check sends text to Google. Keyboard and screen-reader labels throughout. The import itself arrives with the next change.
- The ledger keeps, beside each receipt, what it was graded with (coverage, grant, context) and the policy it was graded under, so an export of your data is exactly what `pnpm attest replay` reads to prove every receipt. Both go with their receipts when the 90-day purge runs (ledger schema version 5).
- Pasted claims are graded: the side panel's Add agent activity sends the claims (never the text) to the service worker, which stores them, grades them against your Gmail Sent folder and Calendar, and says how many were new. A grading batch also runs every 5 minutes, so a claim still being checked is finalised once its grace has passed, even after Chrome stopped the service worker.
- The times in a pasted log count as when the agent was working, and away detection, off unless you turn it on in the options page, lets Chrome tell Attest when you were away from this computer. With both, an email no claim explains is flagged as likely sent by that agent. Away detection asks for Chrome's `idle` permission only when you turn it on, keeps only when each time away began and ended, and deletes all of it when you turn it off (ledger schema version 6).
- A pasted calendar claim now carries its event's start when its words name a day and a time ("Thu 2pm", "Friday at noon", "Oct 8 at 2:00 pm"), so it can be checked against your Calendar; otherwise it stays unverifiable rather than guessed. A pasted entry claims each kind of action once, so a title and the sentence under it never count as two actions.
- An end-to-end test runs the §2 demo through the built extension: Gmail and Calendar pages read by the shipped readers, an agent's log pasted in the side panel, and exactly one verified email, one event not found and one unasked send (likely the agent) in the export. Grading also reads the agent's working times and your time away wherever an unclaimed action lies, not only in the last day.

- The popup shows today's receipts in one glance: the grade first, then the claim, then the agent ("Likely agent" on an unasked action), with what Attest has checked above them ("Gmail not checked since 09:12") and a yellow banner while a reader needs repair. Its first paint over 5,000 receipts must stay under 100 ms, a gate `pnpm bench` measures ([RESULTS.md](RESULTS.md)).
- The side panel's timeline lists every receipt, newest first, filtered by agent, grade and days, with each receipt's detail: the claim, every piece of evidence and its fields, the reasons, what the grading read, and your own mark. A mark (Verified or Not found, with your reason) sits beside Attest's grade, never replaces it, and can be undone.
- The options page sets what each agent may do (actions, recipients, a spend ceiling, declared access) and mutes an agent's alerts; turns each page reader off or on; keeps history for 30, 90 or 180 days; exports the ledger as JSON and the receipts as CSV, a page at a time; and deletes all data, asked twice.
- Alerts: one Chrome notification when a receipt ends Not found, Unasked or Over scope, never naming who, how much or what subject, and never more than one per receipt. A click opens its detail.
- A weekly digest, made every Monday at 09:00 and kept: per agent, the week's receipts by grade and how many checked claims were verified, the receipts to look at, the days a source was not checked, and each reader's health.
- Share a receipt or a week as text or as an image, previewed before you copy it: counterparties by domain only, amounts and times kept, a subject only as its short hint, never what you asked an agent or why you marked a receipt.
- Check Gmail for me, off unless you turn it on: when an agent says it sent an email and no Gmail tab has shown Attest your Sent folder in the 15 minutes since, Attest opens the Sent folder once, in a pinned tab in front of you. It is the one time Attest opens a page itself; the popup says why.
- Every screen passes the axe accessibility checker with no serious or critical problem in light and dark mode, the keyboard reaches every control with a visible focus ring, and nothing moves when your system asks for reduced motion. A test holds the wording to the copy rules: no exclamation marks, buttons that start with a verb, and "Likely agent" on every unasked row.

### Changed

- Chrome permissions (Sprint 4): `scripting`, so the Gmail and Calendar readers are registered while Attest runs, rather than listed in the manifest, and a reader you turn off is unregistered; and `notifications`, for alerts and the weekly digest's notice. The host permissions are unchanged: `mail.google.com` and `calendar.google.com` only. Check Gmail for me opens its tab with no `tabs` permission.
- Ledger schema v8 to v10 (Sprint 4): v8 adds each receipt's `computedMs` and two indexes, so the popup and the timeline read a page at a time over any number of receipts; v9 the `alerts` table; v10 the `digests` table.
- `docs/grading.md` v1.18: a receipt that is not final says from when it can be (`finalFrom`), so the popup's "final from 14:48" is a stored value. No grade, state or reason changed.
- `docs/grading.md` v1.19 (Sprint 5.0): the optional model's score may raise the best candidate's score, but only from a deterministic floor already at or above the partial threshold, never lowering one and never changing which evidence a claim takes, so it can move a partial match toward verified and nothing else. The model weighs 0.15, and the policy loader caps it so the model alone never verifies a partial match. With the model off, which it is until it is wired in, nothing changes. A property test grades 5,000 random inputs with the model's score at 0 and at 1 to prove it.
- Your choices about what Attest may read or open (the readers you turned off, Check Gmail for me) moved from the extension's local storage, which a script on a Gmail or Calendar page could write, into the ledger; an update moves them once. Delete all data keeps a reader you turned off, off.
- `PRIVACY.md` v0.4: the new permissions, Check Gmail for me, alerts, the weekly digest, shares, the readers' on/off choice, the retention choice, Delete all data and the receipts' CSV export. A test holds its permission list to the manifest's.
- The mandatory tests cover Sprint 4: the network-intercept session also runs Check Gmail for me, alerts, a receipt's share and image, the weekly digest and its share, a grant, both exports, a reader turned off and on, and Delete all data; the no-leak test also searches every receipt's share.
- The Gmail Sent, receipt and Google Calendar readers now feed the in-browser ledger (`entrypoints/content/`): the service worker answers each message, stores rows one by one for Gmail and a whole Calendar pass all or none, records which windows were really seen, and keeps Calendar snapshots to tell created, changed and deleted events apart.
- `docs/grading.md` v1.11: a receipt verifies a purchase by its single instant; Gmail Sent coverage comes only from the head of the list; an event Attest found already on the calendar is never UNASKED (first-look markers); a calendar change claim is never NOT FOUND (`coverage.change_unprovable`); with two bound accounts each must be seen whole (`coverage.account_partial`); a match on time alone is no evidence; a calendar view looked at before a claim never makes it NOT FOUND.
- `docs/grading.md` v1.12: no Calendar change is reported as UNASKED until the live smoke can tell the account's own changes from other people's (an invitation Google adds, an organiser's reschedule or cancellation, a colleague's edit on a shared calendar); every Calendar row is stored as a first sighting and still verifies claims. Calendar snapshots keep only each event's first guest address and a one-way key for every other guest; an event updated more than 20 times in a day stores no more updates that day (`ledger.event_churn`); a Calendar page that stays busy through five minutes of passes reports DEGRADED (`page.busy`); and a Calendar coverage window shorter than a day or longer than six weeks is refused.
- Gmail coverage (v1.12): the head of the Sent list no longer vouches for its oldest minute while the list may go on, since an older send in that minute sits on the next page; a receipt from a sender outside the registry is evidence for a claim but never coverage of its own, so a stranger's email can make nothing UNASKED unless a registry receipt dated in the same minute is opened in another pass (a known limit, in `docs/attacks-that-work.md`); a sender name in another script or with look-alike letters ("Аmazon" with a Cyrillic А) is never read as a merchant; and a stranger's long, malformed or undated message never makes the receipt reader DEGRADED.
- All three readers tell which view is shown and which Google account is signed in the same way, in any display language, and read each page once per pass.
- Observers post no coverage while their page is offline or catching up after sleep, a page can no longer stop them, health reports pass the same clock and site checks as rows, and the daily purge never trusts a clock that jumped ahead further than the latest instant the ledger stored (a clock that is ahead while facts are stored at its time is believed; to delete any history it would have to be more than 90 days ahead). Attest does not run in incognito windows.
- A Gmail tab runs one page watcher for both readers and wakes only on changes to what they read; the service worker stores a Gmail pass in a few transactions instead of one per row, and reads only the coverage intervals that can reach a window; the content scripts no longer ship zod's JSON Schema code (Gmail's script from 71,247 to 66,574 bytes gzipped).
- A clock that jumped forward or stepped back no longer lets coverage vouch for hours nobody looked at, and no longer locks a Calendar range out (`clock_behind`, `ledger.clock_regressed`). A Calendar change found long after the last look is never reported as UNASKED, and a visible Calendar tab is read at least once a minute so its changes stay attributable.
- `docs/adapters.md` v1: the observer contract, a pass's post order and acknowledgements, every DEGRADED reason code, `selectors.json` versioning, the capture → label → test → version loop, selector repair, and a section per observer.
- The pre-push hook (`scripts/pre-push.sh`) runs `pnpm test` on the commit each pushed branch or tag points to, in a temporary git worktree, instead of on the working tree: an uncommitted, half-written file can no longer block the push of verified commits or hide a broken one. A commit whose `pnpm-lock.yaml` differs from the installed modules, or that tracks `node_modules` or `extension/.wxt`, is stopped with a message saying what to fix.
- The logger prints only a closed vocabulary of event names and values, plus ULIDs, hashes, ISO timestamps and versions; any other text prints as its length, long numbers as a placeholder, and non-standard error names as `Error`. Every log call names a literal event and literal keys (lint rule `attest/log-call`).
- Lint fences now cover all extension code: no network API outside the two Sprint 5 files, no web storage, IndexedDB only in the ledger, no console aliasing, no Node, runtime messaging only through the bus, no DOM in service-worker code, and inline disables have no effect anywhere. `attest/no-act` also catches indirect calls, destructuring, reflection, DOM insertion, resource loading, and the vendor page's storage; `attest/core-determinism` keeps `src/core` free of clocks, randomness, time zones and locales.
- Stored and bus schemas cap the length of every free-text string and array.
- The no-leak test searches a compact form of every secret (and percent- and base64-decoded text), uses partial-leak canaries for every seed and three identifier-shaped seeds, and also reads web storage, CacheStorage, page storage and cookies.
- The capture sanitiser removes query strings and token fragments from text, `data-*` attributes, `<meta content>` and relative URLs, not only from links.
- On install or update, the install id and the alarms are handled independently; Chrome updates no longer restart the purge countdown.
- Routine bus drops (`no_handler`) and broadcasts nobody hears are logged at debug.
- Timestamps the extension stamps carry the local time-zone offset.
- The toolbar tooltip reads "Attest: receipts for your AI agents".
- CI actions are pinned to commit SHAs, the build artifact uploads again, and CI checks that every `@mandatory` test ran and passed.
- The ledger and the message bus use the grading core's schemas, so stored rows and messages are checked by the same types grading reads.
- `pnpm test` also runs the perf gates, one at a time; `pnpm bench` exits with an error when a gate fails and records the commit and Node version with each result.
- Text is read the way Unicode 15.0 (Chrome 120, the oldest Chrome Attest supports) reads it, on every engine, so a receipt grades and replays the same in every supported Chrome and in Node.
- A policy is refused when one of its rules concludes a grade without the evidence that grade needs (for example a VERIFIED rule with no match at the verified threshold), and grading refuses any policy the loader did not produce.
- A spend claim (a purchase or a subscription change) with no currency counts toward the rolling spend ceiling: two $30 purchases against a $50 ceiling make the second OVER SCOPE, with or without a currency on either.
- Evidence counts only when it comes from a source the policy reads for that kind of action: a row from another source neither verifies a claim nor produces an UNASKED receipt.
- A counterparty, merchant or subject must be one line. An observed row whose allowed field fails its check, or is held by a getter, a setter or a prototype rather than as plain data, is refused whole, never stored without that fact (from Sprint 2 the observer then reports DEGRADED); the ledger also refuses an observation holding a field its source may not store.
- The ledger never rewrites a claim or observation it stores. Seeing it again changes nothing; a sighting earlier than the stored one that arrives late is refused (from Sprint 2 the observer then reports DEGRADED), and so is a claim or observation that differs from the stored one under the same hash, rather than keeping either silently. A claim read again by a newer extractor that reads it the same way is the same claim.
- A new claim or observation is stamped no earlier than the moment it is stored and after the last grading run, and each grading run records its time before it reads, strictly after the run before it. So replay rebuilds every grading from exactly the rows it read.
- Health reports carry reason codes such as `selector.missing`, never page text, and adapter, observer and extractor ids are short tokens. A request's conversation id is the vendor's own id, never a title or a line of the chat, and each granted scope and allowlist entry is one line.
- A purchase never counts as its own earlier spend under the rolling spend ceiling: the same purchase read twice (an activity view shown again seconds later) is one claim, counted once.
- A claim too vague to match, or a calendar claim with no event time, is never called NOT FOUND, whatever order a policy puts its rules in; a policy whose partial-match threshold is 0 is refused, and so is one whose UNASKED threshold is 0, since an accusation must rest on a signal that counts.
- An override changes only the gradings that start after it, and a claim overridden to VERIFIED keeps its evidence: no other claim can take that email or event. Replay rebuilds each grading exactly as it ran.
- Undoing an override keeps it in the receipt's history with the time it was undone, so the gradings made while it stood still replay. If another claim took the evidence meanwhile, the evidence stays with that claim.
- Text holding half of a broken character pair (a lone surrogate) reads as the replacement character U+FFFD on every engine, so removing an invisible mark can never join two halves into a character the text did not hold.
- `pnpm attest replay` escapes control and invisible characters from the export, and from the file name it echoes, line breaks included, before it prints them, so a crafted file or file name cannot drive your terminal or forge an output line.
- Lint: `src/core` may import only its own modules, `zod` and the policy file, and may not use `WeakRef`, `FinalizationRegistry` or `Temporal`, read `.constructor`, parse text with `new Date(text)`, or turn a date into text through the host's time zone (`date.toString()`, `String(date)`). No shipped file may hold an ambient `declare`, which could hide a real global from these rules. The Unicode fence reads the syntax tree of every file under `src/core`, not its text, and refuses case-insensitive patterns that fold beyond ASCII, a backreference under `i`, and inline modifier groups. `src/core` may also not read an error stack or `import.meta`, use `Atomics` or `SharedArrayBuffer`, use reflection beyond `Reflect.get`, `Reflect.has` and `Reflect.isExtensible`, call `.call`, `.apply` or `.bind`, or stack type assertions. `src/core` may read only the ES2023 built-ins on an allowlist (any other global, such as `Image` or `clientInformation`, fails lint and the grep test), may not switch the type check off (`@ts-expect-error`, `@ts-ignore`, `@ts-nocheck`, triple-slash references), and reads `RegExp` only as `new RegExp(…)`. Every test's timeout is checked as the test runs.
- `docs/grading.md` v1.13: a Gmail Sent row that holds a conversation (several messages) gives no row, since its time is its newest message's and not a send's, and the window the head of the Sent list vouches for starts a minute after the newest such row. A reply sent inside a thread is therefore UNVERIFIABLE from the Sent list, never NOT FOUND. A Calendar event the page shows that the reader cannot read makes the pass DEGRADED (`event.unreadable`) instead of being left out, and a Calendar month view is DEGRADED until its events can be placed on days.
- The readers now match real Gmail and Google Calendar pages (first real captures, 2026-10-06): Gmail's hidden screen-reader copy of each Sent row is not read as a second subject or extra recipients; a receipt's message is found where real Gmail puts its id (before, no real receipt was read); a second signed-in Google account is read from its account label; Calendar's calendar list is read from its native checkboxes by their live ticked state, and lists still filling in mean the page is still drawing.
- `pnpm capture` records a checkbox's live ticked state, takes `--keep-selector` for areas where a redacted text must not be replaced, fakes the name inside Google's short calendar ids within event ids, and no longer copies the page's own stylesheets (each element's computed styles are already written inline; Gmail's are about 4 MB a page). A link to another site keeps only its scheme and host, read as Chrome reads it, and so does a web address written as text or in an attribute; a phone or place link keeps only its scheme; a card ending is faked, and so are digits glued to a name. A line of 100,000 bullets no longer takes 22 s to clean.
- An email you send to yourself no longer stores your address: the Gmail Sent reader leaves your own mailbox out of a message's recipients in any spelling (any case, a `+tag`, Gmail's dots), as the Calendar reader does with guests; a message sent only to yourself gives no row, and a claim about it is UNVERIFIABLE, never NOT FOUND. Your own mail gets no receipt parser, and on a page that names no account Attest reads no generic receipt and stores no guest.
- `docs/grading.md` v1.14: an email claim is NOT FOUND only on a view of the Sent list taken after its grace period, since a list read sooner may not yet show a reply an agent sent from elsewhere (`coverage.list_unsettled`); a view taken too early is named as a reason only for a span no later view saw; the ledger merges Sent views only when the later one contains the earlier.
- The Gmail Sent reader refuses a row whose ids are blank or not in Gmail's form, and a list out of order vouches for no window; a Calendar page with an empty calendar list never says every calendar is shown; a list inside an email is never read as a message.
- Receipts read from real mail (captures of 2026-10-07): a Stripe receipt whose total label sits in a small table of its own beside the amount is read; Uber's charge summary, which says it is not a payment receipt, is no longer a second purchase of the same trip; an amount in "Rs.", a sign several countries' rupees share, is never given a currency: the receipt shows as unreadable instead of guessed.
- `docs/grading.md` v1.15: an email you composed as a draft before sending is read from the Gmail Sent list as the send it is. Gmail keeps the draft's thread id, which made such a mail look like a conversation, so it gave no row; a third of the rows on the real Sent pages were single sends read that way. A row is now one message when Gmail shows no message count beside it on a list that shows counts; a row with a count is still a conversation, and a list that shows no count is read by its ids alone.
- With several Gmail tabs open, a tab on another folder no longer changes how healthy the Gmail readers look: a page a reader does not read reports IDLE (nothing to read, nothing wrong), which never replaces the status the Sent tab or an opened receipt gave, so a reader that broke stays shown as broken. When the same tab moves on, its earlier status gives way to idle, so a passing hiccup does not stay on screen.
- `pnpm capture` fakes every value with a secret key kept outside the repository (`~/.config/attest/capture-key`, made on first use) and refuses a public seed, so a committed capture's fakes cannot be worked back to your values; `capture-refake.ts` re-fakes an older capture without its originals. It also fakes card endings and order numbers that a receipt's table rows label, codes beside their labels (referral, coupon, tracking, booking, membership), Google Meet codes, postal addresses written over several lines, written web addresses with no scheme, and ids inside page attributes.
- `pnpm bench` refuses to publish numbers measured on uncommitted code (`pnpm bench -- --dirty` for a look).
- CI runs as five jobs side by side, each inside its 30 minutes (the slowest measured at 20.3), with one shared setup step and each test worker's memory pinned to 2 GB.
- Attest's readers for Muse, ChatGPT and Claude are off: Meta's, OpenAI's and Anthropic's terms do not allow collecting data from their sites by automated means. The options page lists each reader, on or off, and why, and Attest asks for access to Gmail and Google Calendar only (PRIVACY.md version 0.1).
- Grading ranks a batch's candidate ids by number rather than as text, halving that step (37 → 18 ms per 5,000-claim bench batch) with every receipt unchanged.
- `docs/grading.md` v1.16: when the computer's clock was wrong and is set right, a calendar event an agent said it created is never NOT FOUND because of it. Attest now keeps the span of time the wrong clock may have stamped, and a claim stamped in it is UNVERIFIABLE (`coverage.clock_repaired`) when its event was first seen only after the fix. Before, the event's sighting could read as older than the claim and be ruled out, so a true claim was NOT FOUND (golden 114).
- Each receipt's replay record names its grading batch's coverage instead of copying it (schema v7): a batch's coverage is stored once, so the records no longer grow by tens of kilobytes per receipt with every Calendar event in view, and the export stays small enough to save and replay.
- The paste screens say what Attest keeps: the actions it finds and the times of the log's entries, never the text, and the preview counts the times it keeps.
- A pasted log is read more carefully: a heading such as "September" or "2 weeks ago" no longer lends the day of the heading above it, a time copied with full-width digits or an invisible character is still the time, the same log copied in another Unicode form gives the same claims, a moved event's new start is the one read, and a log too long to send is refused up front with a message.
- Grading every five minutes costs almost nothing when there is nothing to grade, and a grading batch the alarm runs tells open pages when a receipt changed.
- A time away left open when Chrome closes is no longer stretched over the next day, and a clock set back after running ahead no longer leaves future times away or session times behind.
- `docs/grading.md` v1.17: one line of a pasted activity log counts once as evidence that the agent was working. Its time was counted twice, as the agent's session and as its activity, so one pasted calendar action could make a send of your own, two minutes later, UNASKED "likely the agent" (golden 115).
